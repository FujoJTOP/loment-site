Releases

Release history

From the first Loment to the one being built now. Each entry says what that version was for — and where the record of it lives, because the earliest ones were released from a different repository and this one does not carry their tags.

Download Get started

This is the one page on this site that names versions. Everywhere else the download link says releases/latest, because a version number written on a page is a fact with an expiry date. Here the versions are the subject, so they are named and each one points at what was actually published. None of it is a promise about a version that has not shipped.

Before this repository

The first six versions came out of the project's previous repository. Their tags are not in this one and neither are their dates, so what follows is the shape of the line rather than a dated record — and nothing here links anywhere, because there is nothing to link to.

0.1.1 — the first Loment

A strict subset of Rust's syntax. That was the opening constraint rather than a style: the language was defined by what Rust had already settled, so there was very little to argue about and a compiler to build. It no longer claims to be a subset — the overlap is still there, the claim was dropped when the surface grew past it.

0.1.2 Alpha — the first self-hosting

The language begins to be written in itself. What that buys is not elegance: a compiler written in the language it compiles is the only way to find out what the language cannot express.

0.1.2 pre1 — repairs

The problems the first self-hosting turned up. A pre-release is where that kind of thing is supposed to happen.

0.1.2 pre2 — the base that still stands

The bootstrapping foundation every release since is built on: a compiler that rebuilds itself from a seed committed to the repository, and a check that the rebuilt seed equals the one it started from.

0.1.3 Alpha — the multi-syntax idea arrives

The first version where another language's source can be read as Loment. The meaning is always this language's; only the spelling is borrowed. It is the project's founding argument rather than a feature added on top, which is why it is listed here and not under "what else is different".

0.1.3.4 Alpha — the loop closes

All four stages — lexer, parser, checker and code generator — written in Loment, and the result reaches a three-stage fixed point. This is the last of the versions released from the previous repository, and the one every later version is measured against: it is the release the language and the compiler stopped needing a host to define them.

0.1.4 Pre

2026-09-22. The first release from this repository, and the first Loment you could install without building it. It was put up as a pre-release for one reason: so that "the repository has versions" stops being a claim and becomes a fact you can look at.

One artefact of how it was made is worth knowing if you go looking: the tag points at an earlier commit than the archives were built from. GitHub's automatically generated source archives follow the tag, so the source you download that way is the tree before that build.

0.1.4 — usable

2026-09-23. The version whose subject was being usable rather than having more in it. The language surface did not change at all — no new syntax, no new built-ins — and the work went into getting the last of the interpreter out of the path: the package manager and the generator for the low-level interface files gained Loment implementations, judged the only way that means anything, byte for byte against the Python ones they replaced.

Compatibility was stated at the time and is worth repeating, because it is the kind of thing a version number hides: nothing written in Loment had to change, and the generated low-level artefacts came out byte-identical. The bootstrap seed did change, so anyone rebuilding a toolchain from a seed needs the new one. The package filenames carry the version, as they must.

The Windows installer published with this version does not work on every machine, and it will not be replaced. On some systems, double-clicking it produces no window and no error — the process simply exits. The cause is understood: the self-extracting package runs the installer script by name without a path, and on machines where Windows is configured not to search the current directory, that name cannot be found. The same file therefore installs normally on one machine and silently does nothing on another. Install from the zip archive instead, which contains the same thing. The fix is written and ships with a later version; the published installer is left alone on purpose, because rebuilding it would change the bytes of a file that already has a version number attached. See issue #117.

0.1.4.5

Being released. The tag that stands today is an announcement — it carries no archives and no installers. The release is being cut from it, and this is what it contains: what is new, and what was broken and now is not.

New

  1. Reclamation is complete. The four-rung ladder — static promotion, last-use, block epochs, and the runtime collector — has implementations on both sides and a criterion for each; an adaptive collector for the tier that wanted one; and a generational half, with a card table and a write barrier. How much of a program the collector is responsible for is a number the artifact carries, and two independent validators check it without reading a line of source. See LomentGC.
  2. no_runtime is a guarantee, not a declaration. The default used to mean "this program did not ask for a runtime". It now means the artifact has none: a construct that would drag one in is refused at compile time. choose runtime is the other half — it puts the runtime in whether or not the program uses it. This is the one change here that can affect a program you already have: anything using division, allocation or string building needs one line added to its root unit.
  3. A fifth dimension: vm. A program can now say which execution model it is for. In a release build that line is a compile error; only the development channel accepts it, and what that channel produces is byte-identical to no_vm. The dimension and the gate are real, and the engine is not — that page says which half is which.
  4. Networking, on both targets. The same source opens a socket on Linux and on Windows, from the same bytes. Two boundaries come with it, and they are the parts still missing: there is no networking library — you write the system calls — and there is no admission gate, so a unit that declares it will not request network access is not actually stopped from calling a socket. The capability check compares the names of domains, and never looks at behaviour.
  5. --opt. When clang is installed, the build can hand it the IR at -O2 instead of using the bundled linker. It is the fast path, and it costs the property the bundled path exists for: no external toolchain required.

Fixed

  1. The Windows installer. The one published with 0.1.4 does nothing at all on a machine configured not to search the current directory for an executable. That one stays as it is; this release carries the fixed installer.
  2. A free list that never reused anything. The bundled linker assigned only one incoming edge per phi, so the allocator's free list stayed empty for its whole life.
  3. Artifacts the assembler refused. Two IR bugs made array-subscript artifacts invalid LLVM. And a missing block terminator in the collector's own output was invisible to every criterion the project had.
  4. The language server and the formatter. The server no longer crashes on a file it cannot parse, and the self-hosted formatter no longer refuses the six other surface grammars.
  5. Stack alignment at the entry point. A process entry is not given the alignment the call convention assumes, so _start realigns it.
  6. Several fixes in the C surface grammar for the places the front end swallowed something or reported it as something else. Each has its own issue; the tag message lists them.

Not in this release

libc and LibL are not available. The libc line is building the pieces a C library needs one at a time, and the standard library's libc-shaped face is not ready to be used. Neither is something to plan around today — the LibL page carries its own status line.

Where the current state is

This page is history. What the project can do today is on the rest of the site and in the repository, and what it intends to do next is on the roadmap — which is written as a plan and says so.
