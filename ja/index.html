システムプログラミング言語

Loment

Loment は、それだけで立つネイティブの実行ファイルを作る —— runtime も libc も、その下に何もない。プログラムが何に届いてよいかはソースに書かれ、バイナリに 記録されるので、ビルドはあなたのコードを読まずにそれを検査できる。ツールチェイン自体も Loment で書かれている。

ダウンロード はじめに 

module hello fn _start() {    let s: str = "hello from Loment\n";    syscall4(1, 1, str_ptr(s) as u64, str_len(s) as u64);    syscall4(60, 0, 0, 0);}

$ loment run hello.lomt
hello from Loment

これがプログラムの全体である。_start はマシンが始まる場所で、テキストは write システムコールを通って出ていく —— 何もリンクしないプログラムには、 その下に呼ぶべき printf がない。何もあなたの代わりにされず、何も邪魔を しない。

二種類のプログラム

多くの言語は、バイナリに何を入れるかをビルドファイルで決める —— ソースを読む人が決して 開かないファイルである。Loment はその決定をプログラムの内側に置く: 自分が始める ファイルに書く一行であり、それはバイナリが携える機械可読な要約へと引き継がれる。だから 「これはどちらの種類のプログラムか?」は、コードを一切読まずに答えられる。

choose sealed

これは何か
既定。外界への開口を持たないプログラム。
エントリポイント
fn _start()
リンク
なし。未定義シンボルは警告ではなくエラーである —— だから sealed なプログラムが runtime も libc も積まないことが証明できる。
到達範囲
それにコンパイルされたコードだけ、加えてリンカに渡したオブジェクトのうち既に 自己完結しているもの。

choose hosted

これは何か
もう一方の道。自分自身の外に届くことを許されたプログラム。
エントリポイント
fn main() -> u32
リンク
実在のライブラリ。ビルドはその出力を、Loment に同梱のリンカではなくホストの C ツールチェインに渡す。
到達範囲
libc、共有ライブラリ、そして自分で埋め込むホスト runtime。プロジェクト自身の判据は libstdc++ と libz をリンクし、CPython を埋め込む。

境界は、正確にはここにある。実在のライブラリに届くとは、自分でホストの ツールチェインを通すということだ —— ビルドでそのライブラリを名指しする。実在の C ライブラリは まだインストール可能な依存ではない。パッケージマネージャが受け取るのは今も Loment の ソースライブラリだけである。その部分は作っている途中だ。

プログラムが触れてよいもの

多くの言語はこのプログラムは何ができるか?に答える —— そして答えはたいてい 「好きなこと全部」である。Loment はもっと狭い問いを軸に組み立てられている: このプログラムは何に届くことを許されていて、それはソースを読まずに決着できる か?それを支えるのは三つで、最初のものはコードの中に見える。 

module native_cap capability blk_write : disk[0..4] revocable fn write(slot: u32) -> u32 {    guard blk_write(slot);    return slot;} fn literal_ok() -> u32 {    guard blk_write(2);    return 2;}

3 行目がユニットの届いてよい範囲を宣言する。6 行目は slot を実行時にそれと 照合し、範囲外の添字はプログラムを止める。11 行目はリテラルなので、コンパイラが前もって 決着させ、何も出力しない。

コードが宣言する範囲

ユニット —— ひとつのソースファイルと、それが取り込むもの —— は届いてよい範囲を宣言し、 guard が個々のアクセスをその範囲と照合する: 添字が定数ならコンパイル時に、 そうでなければ実行時に。Loment はこれをケイパビリティドメインと呼び、境界を うやむやにせず明示する —— guard が区切るのは添字であって対象では なく、またそれは認可ではない。

バイナリが携える要約

すべてのユニットは、自分が何を含み何に届くかを書いた機械可読な要約をエクスポートし、 二つの独立したプログラムがそれを検査する。だから「これは何に触れうるか?」には、 あなたのコードを読まずに答えがある。その要約には名前がある: 形式オブジェクト。

他の十の言語からコードを呼ぶ

C、C++、Rust、Zig は C ABI を通って入ってくる。Go、Python、Java、JavaScript、Perl、 Lua はプロセスブリッジを通って。sealed なプログラムでは、リンクするものはどれも 自己完結していなければならない。choose hosted が実在のライブラリへの道で あり、プロジェクトのテストはそれを libstdc++、libz、埋め込んだ CPython に対して 走らせる。

それで既に作られているもの

これほど若い言語は、たいてい「何になりたいか」で語られる。ここにあるのは、Loment が すでにしていることだ —— すべてリポジトリの中にあり、すべてダウンロードできる。

ツールチェイン

コンパイラ、リンカ、フォーマッタ、ランゲージサーバ、そしてパッケージマネージャは、 どれも Loment のソースとして出荷され、その下に Python なしで動く。コンパイラは、 この言語で書かれた最大のプログラムである。

ディスクドライバ

ahci.lomt は SATA ディスクと話す: レジスタブロックを読み、実装されて いるポートを数え、コマンドを発行する。レジスタブロックは呼び出し側が渡すので、同じ コードがオペレーティングシステムの中でも、hosted なマシン上でも動く。

ターミナルインターフェース

lumtui はテキスト、枠、レイアウトをターミナルに描く —— 小さな ライブラリで、あなたが自分のものを書くのと同じやり方で書かれている。

コンパイラは loment/selfhost/ の下に、ライブラリは loment/lib/ の下に、サンプルは loment/examples/ の下にある。

ほかに何が違うか

プログラム全体の設定を、一行で

自分が始めるファイルに書く一行が、プログラム全体について五つのことを決める: ライブラリのどの層を使ってよいか、メモリをどう回収するか、runtime を積んでよいか、 自分自身の外に届いてよいか、そしてどの実行モデル向けに書かれたか。矛盾する二つの 設定を求めれば、コンパイラは拒否する —— 「不正な組み合わせ」と言う代わりに、その 両方を名指しし、理由を述べる。この仕組みは choose と呼ばれる。

六つの別の構文でも書ける

C、C++、Java、C#、Go、Python。変わるのは綴りだけで、意味は常に Loment のものである —— それは構文であって意味論ではなく、各フロントエンドはそのことを自分の最初の行に 書いている。

モジュールをひとつずつ取り込むライブラリ

標準ライブラリはツールチェインに同梱され、use vec、use map、 use fs のようにひとつずつ届く。すべてを一度に引き込むパッケージ全体の 取り込み口もあるが、ドキュメントはそれを使わないよう勧めている。

すべてがカスタマイズできる

ソースの拡張子、実行できるコマンドの集合、ライブラリ —— その同一性が内容ハッシュで あるディレクトリ —— そしてツールチェインそのもの。レジストリはない。拡張点はディスク 上のファイルである。

まだ終わっていないこと。ツールチェインは Python も libc もなしで コンパイルし実行する —— だが開発側はまだそこに至っていない。参照実装とそのテスト群は 今もリポジトリにあり、リポジトリはまだ「Loment だけ」ではない。残っている項目がどちらの 半分に属するかはリリースノートに書かれている。

システム

Loment のうち、独自の設計記録を持てるほど大きい四つの部分 —— それぞれが正直な現状の 一行を持ち、エンジンがまだ存在しないものも含む。

LomentGC メモリは、それが起きる場所ごとに選ばれる四つの戦略のいずれかで解放され —— コレクタにどれだけ任されるかはバイナリに書き込まれる。 LVM — Loment VM プログラムを走らせる第二の方法 —— 実行者が要求に応じて採用するバイナリ。エンジンは存在せず、そのページはまずそう述べている。 lompi ライブラリとは Loment ファイルのディレクトリである。マニフェスト言語もバージョン解決器もなく、同一性は内容ハッシュ。 LibL 標準ライブラリの C の形をした面。名前も引数の順も C のままで、判定基準は Python ではなく実物の glibc と比べる。

もっと読むには

学習 効く順番と、各段に何が足りないか —— 並べて書いてある。 はじめに インストールして最初のプログラムを走らせる。ネイティブバイナリ。Python も clang も WSL も要らない。 VS Code 拡張 ハイライト、言語サーバー、ビルドとデバッグのコマンド —— それ自身のツールチェインではなく、チェックアウトのためのクライアントである。 サンプル 短いプログラム。それぞれが出力したものを添えて —— そしてそれらに含まれないものも。 標準 LLS: 引用できる標準として書き下されたこの言語 —— 何が凍結され、何が適合を決めるのか。 さらに多くのサンプル リポジトリにある全部。そのすべてが今日リンクするわけではない。 リリース履歴 最初の Loment から、いま作っているものまで —— 各版が何のためのものだったか。 ロードマップ プロジェクトが目指している各版と、それぞれが何のためのものか —— 計画であって、約束ではない。 Wiki 言語、ツールチェイン、ロードマップを、ページごとに。 README 何のためにあるのか、ほかに何が違うのか、そして正直に言って何がまだ終わっていないのか。 Discord プロジェクトが話をする場所。質問はバグ報告と同じくらい歓迎される。
