リリース

リリース履歴

最初の Loment から、いま作られているものまで。各項目は、そのバージョンが何の ためだったか —— そしてその記録がどこにあるかを述べる。最も初期のものは 別のリポジトリからリリースされており、このリポジトリはそれらのタグを持っていないからである。

ダウンロード はじめに

これはこのサイトで唯一、バージョンを名指しするページである。他のどこでも ダウンロードリンクは releases/latest と言う。ページに書かれたバージョン番号は 賞味期限つきの事実だからである。ここではバージョンこそが主題なので、それらは 名指しされ、それぞれが実際に公開されたものを指し示す。そのいずれも、まだ出荷されて いないバージョンについての約束ではない。

このリポジトリより前

最初の六つのバージョンは、プロジェクトの以前のリポジトリから出た。それらのタグも日付も このリポジトリにはないので、以下に続くのは日付つきの記録ではなく、線の形である —— そしてここでは何もどこにもリンクしない。リンクする先が何もないからである。

0.1.1 —— 最初の Loment

Rust の構文の厳密な部分集合。それは様式ではなく、出発点の制約だった: 言語は Rust がすでに決着させたものによって定義され、だから議論すべきことはごくわずかで、 作るべきコンパイラがあった。もはや部分集合であるとは主張していない —— 重なりは いまもあるが、表層がそれを越えて育ったときにその主張は取り下げられた。

0.1.2 Alpha —— 最初のセルフホスト

言語がそれ自身で書かれ始める。それで得られるものは優雅さではない: 自分がコンパイルする 言語で書かれたコンパイラだけが、その言語が表現できないものを見つけ出す唯一の方法である。

0.1.2 pre1 —— 修復

最初のセルフホストが明らかにした問題。その種のことはプレリリースで起きるものとされている。

0.1.2 pre2 —— いまも立ち続ける基盤

それ以降のあらゆるリリースがその上に建てられているブートストラップの基盤: リポジトリに コミットされた種から自分自身を再構築するコンパイラ、そして再構築された種が始めたときの ものと等しいことの検査。

0.1.3 Alpha —— マルチシンタックスの発想が到来する

別の言語のソースを Loment として読める最初のバージョン。意味はつねにこの言語のものであり、 借りているのは綴りだけである。それは後から足された機能ではなく、プロジェクトの創設の論で あり、だから「ほかに何が違うか」の下ではなくここに挙げられている。

0.1.3.4 Alpha —— 一巡が閉じる

四つの段階 —— 字句解析器、構文解析器、検査器、コード生成器 —— がすべて Loment で 書かれ、その結果は三段階の不動点に到達する。これは以前のリポジトリからリリースされた 最後のバージョンであり、それ以降のあらゆるバージョンが測られる基準である: 言語とコンパイラが、自分たちを定義するのにホストを必要としなくなった リリースである。

0.1.4 Pre

2026-09-22. このリポジトリからの最初のリリースであり、ビルドせずに インストールできる最初の Loment。ひとつの理由でプレリリースとして置かれた: 「リポジトリにバージョンがある」が主張であることをやめ、見ることのできる事実になるように。

それがどう作られたかのひとつの痕跡は、探しに行くなら知っておく価値がある: タグは アーカイブがビルドされたコミットより前のコミットを指している。GitHub が自動生成する ソースアーカイブはタグに従うので、その方法でダウンロードしたソースはそのビルドより前の ツリーである。

0.1.4 —— 使える

2026-09-23. 主題がより多くを持つことではなく使えること だったバージョン。言語の表層はまったく変わらなかった —— 新しい構文も、新しい組み込みも ない —— そして作業は、最後のインタプリタを経路から追い出すことに注がれた: パッケージ マネージャと低レベルインターフェースファイルの生成器が Loment の実装を得て、それが意味を 持つ唯一の方法で、置き換えた Python のものとバイト単位で比較して判定された。

互換性は当時述べられ、繰り返す価値がある。それはバージョン番号が隠してしまう類のもの だからである: Loment で書かれたものは何ひとつ変える必要がなかった、 そして生成された低レベルの成果物はバイト単位で同一に出た。ブートストラップの種は変わった ので、種からツールチェインを再構築する者には新しいものが必要である。パッケージの ファイル名は、そうでなければならない通り、バージョンを運んでいる。

このバージョンで公開された Windows インストーラは、すべてのマシンで動くわけでは なく、置き換えられもしない。一部のシステムでは、ダブルクリックしてもウィンドウも エラーも出ない —— プロセスはただ終了する。原因は判明している: 自己展開パッケージが インストーラスクリプトをパスなしで名前だけによって走らせるので、Windows がカレント ディレクトリを検索しないよう構成されたマシンでは、その名前が見つからない。だから同じ ファイルが、あるマシンでは正常にインストールし、別のマシンでは黙って何もしない。 代わりに zip アーカイブからインストールすること。それには同じものが 入っている。修正は書かれ、後のバージョンとともに出荷される。公開済みのインストーラは 意図的にそのままにされる。再構築すると、すでにバージョン番号が付いているファイルの バイトが変わってしまうからである。 イシュー #117 を見よ。

0.1.4.5

リリース中。今日立っているタグは告知である —— アーカイブもインストーラも 運んでいない。リリースはそこから切られつつあり、これがその内容である: 何が新しく、 何が壊れていて、いまはそうでないか。

新規

  1. 回収は完了した。四段のはしご —— 静的昇格、最終使用、ブロックエポック、 そして実行時コレクタ —— は、両側に実装を持ち、それぞれに判据を持つ。それを必要とした 段階のための適応的コレクタ; そしてカードテーブルとライトバリアを備えた 世代別の半身。コレクタがプログラムのどれだけに責任を持つかは成果物が運ぶ数で あり、二つの独立した検証器がソースを一行も読まずにそれを確かめる。 LomentGC を見よ。
  2. no_runtime は宣言ではなく保証である。既定はかつて 「このプログラムは runtime を求めなかった」という意味だった。いまは成果物が それを一切持たないという意味である: runtime を引き込んでしまう構文はコンパイル時に 拒否される。choose runtime はその反対の半身である —— プログラムが使うか どうかに関わらず runtime を入れ込む。ここで唯一、あなたがすでに持っている プログラムに影響しうる変更がこれである: 除算、確保、または文字列構築を使う ものは、そのルートユニットに一行を足す必要がある。
  3. 第五の次元: vm。プログラムは、自分がどの実行モデル向けかを いま言える。リリースビルドではその行はコンパイルエラーであり、開発 チャネルだけがそれを受け入れる —— そしてそのチャネルが生むものは no_vm と バイト単位で同一である。次元とゲートは実在し、エンジンは実在しない —— あのページがどちらの半身がどちらかを述べている。
  4. ネットワーキング、両方のターゲットで。同じソースが Linux でも Windows でも、 同じバイトからソケットを開く。それとともに二つの境界が来る。そしてそれらは依然として 欠けている部分である: ネットワーキングライブラリは存在しない —— システムコールは自分で書く —— そして受け入れゲートは存在しない。だから ネットワークアクセスを要求しないと宣言した単位が、ソケットを呼ぶことを実際に止められては いない。ケイパビリティ検査はドメインの名前を比較するだけで、振る舞いを決して 見ない。
  5. --opt。clang がインストールされていれば、ビルドは同梱の リンカを使う代わりに、IR を -O2 で clang に渡せる。それは速い道であり、 同梱の道が存在する理由である性質を犠牲にする: 外部ツールチェインを必要としないこと。

修正

  1. Windows インストーラ。0.1.4 とともに公開されたものは、実行ファイルを カレントディレクトリから探さないよう設定されたマシンでは、まったく何もしない。それは そのままにされる; 本リリースは修正済みのインストーラを運ぶ。
  2. 何も再利用しなかったフリーリスト。同梱のリンカが phi ごとに入ってくる 辺をひとつしか代入していなかったので、アロケータのフリーリストはその全生涯を通じて 空のままだった。
  3. アセンブラが拒否した成果物。二つの IR の欠陥が、配列添字の成果物を 不正な LLVM にしていた。そしてコレクタ自身の出力に欠けていたブロック終端は、 プロジェクトが持っていたあらゆる判据に対して不可視だった。
  4. 言語サーバーとフォーマッタ。サーバーはもはや、解析できないファイルで クラッシュしない。そして自己ホストのフォーマッタはもはや、他の六つの表層文法を 拒まない。
  5. エントリポイントでのスタック整列。プロセスのエントリには、呼び出し規約が 前提とする整列が与えられないため、_start がそれを整列し直す。
  6. C の表層文法におけるいくつかの修正 —— フロントエンドが何かを呑み込んだり、 別の何かとして報告したりした箇所のための。それぞれに独自のイシューがあり、タグの メッセージがそれらを列挙している。

本版には入っていない

libc と LibL は利用できない。libc の線は、C ライブラリが必要とする部品を ひとつずつ組み立てており、標準ライブラリの libc の形をした面は、使える状態にはなっていない。 どちらも今日計画を立てる対象ではない —— LibL のページが独自の 状態行を携えている。

現在の状態はどこにあるか

このページは履歴である。プロジェクトが今日できることは、サイトの残りとリポジトリに あり、次に何をしようとしているかはロードマップにある —— それは計画として書かれ、 そう述べている。

最新リリース インストールすべきバージョン。つねにこのリンクであり、ページに書き写されたバージョン番号ではない。 ロードマップ 0.1.4.5 の後に来るもの。機能としてではなく、計画として述べられている。 はじめに インストールして、最初のプログラムを走らせる。 フロントページへ戻る Loment とは何か、そしてそれがビルドする二種類の成果物。
