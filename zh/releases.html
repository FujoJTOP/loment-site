发布

发布历程

从最早的 Loment 到此刻正在构建的这一版。每一条都说明那一版是为了什么 —— 以及 它的记录在哪里，因为最早的那些版本是从另一个仓库发布的，而这个仓库并不带着它们的标签。

下载 入门

这是本站唯一一页写出具体版本号的页面。别处下载链接一律写 releases/latest，因为写在页面上的版本号是一个会过期的说法。而这里 版本本身就是主题，所以它们被写出来，每一个都指向当时真正发布的东西。 其中没有任何一条是对尚未发布的版本所作的承诺。

在这个仓库之前

最早六个版本出自这个项目之前的那个仓库。它们的标签不在这个仓库里，日期也不在，所以 下面给出的是这条线的形状，而不是一份带日期的记录 —— 而且这里没有一处链接，因为没有 什么可链。

0.1.1 —— 第一个 Loment

Rust 语法的严格子集。那是最初的约束，而不是一种风格：这门语言由 Rust 已经定下来的东西来定义，所以几乎没有什么可争的，需要的只是把编译器建起来。 它如今不再声称是子集 — 重叠面还在，只是当语法面长过它之后，那个说法被撤掉了。

0.1.2 Alpha —— 第一次自举

这门语言开始用自身来写。它买到的不是优雅：一个用它自己所编译的语言写成的编译器， 是找出这门语言表达不了什么的唯一办法。

0.1.2 pre1 —— 修补

第一次自举暴露出来的那些问题。预发布正是这类东西该发生的地方。

0.1.2 pre2 —— 至今仍立着的地基

此后每一次发布都建在它之上的自举地基：一个从提交进仓库的种子重建自身的编译器， 以及一条"重建出来的种子等于它出发时的那个"的判据。

0.1.3 Alpha —— 多语法这个想法到来

第一个可以把另一种语言的源码当作 Loment 来读的版本。语义永远是这门语言的，借来的 只是拼写。它是这个项目的立论，而不是后来加上去的一个功能，所以它列在这里，而不列 在"还有什么不同"下面。

0.1.3.4 Alpha —— 闭环

四个阶段 —— 词法分析器、解析器、检查器和代码生成器 —— 全部用 Loment 写成，产物 到达一个三阶段的定点。这是从上一个仓库发布的最后一个版本，也是此后每一个版本拿来 对照的那一版：它是语言与编译器不再需要一个宿主来定义自己的那个发布。

0.1.4 Pre

2026-09-22。从这个仓库发布的第一个版本，也是第一个不用自己构建就能 安装的 Loment。它被当作预发布挂出来只有一个原因：让"这个仓库是有版本的"不再是一句 声称，而变成一件你看得见的事实。

如果你要去翻，有一处制作上的细节值得知道：标签指向的 commit 比归档包所构建自 的那个更早。GitHub 自动生成的源码归档包跟着标签走，所以你那样下载到的源码，是那次 构建之前的树。

0.1.4 —— 可用

2026-09-23。这一版的主题是可用，而不是往里塞更多东西。语法面 完全没有变 —— 没有新语法，没有新内建 —— 力气都花在把解释器最后一点从必经之路上拿掉： 包管理器和那个生成底层接口文件的生成器都获得了 Loment 实现，而判断它们的方式只有一个 才算数，就是与它们所取代的 Python 实现逐字节对比。

兼容性在当初就说明过，值得再说一遍，因为这是那种会被版本号盖住的事：用 Loment 写的任何东西都不必改，而生成出来的底层文件逐字节相同。自举种子确实变了，所以 任何从种子重建工具链的人都需要新的那一个。包文件名带着版本号，这是必须的。

随这一版发布的 Windows 安装器并不是在每台机器上都能用，而且它不会被重打。 在某些系统上，双击它会既不弹窗、也不报错 —— 进程直接退出。原因已经清楚：这个自解压包 按名字、不带路径去运行安装脚本，而在那些把 Windows 配置成不搜索当前目录的机器上，这个 名字找不到。于是同一个文件在一台机器上能正常安装，在另一台上却悄无声息地什么也不做。 改为从 zip 压缩包安装，里面装的是同一个东西。修复已经写好，会随之后的 某个版本发出；那个已发布的安装器是有意留着不动的，因为重打它会改动一个已经附上版本号的 文件里的字节。见 issue #117。

0.1.4.5

正在发布。今天挂着的这个标签是一则公告 —— 它不带归档包，也不带安装器。 这一版正从它上面切出来，以下是它的内容：哪些是新增的，哪些坏了、而现在不坏了。

新增

  1. 回收已经完成。四级阶梯 —— 静态提升、定活、块纪元，以及运行时收集器 —— 两边都有实现，每一级都有一条判据；为需要它的那一档所做的一个自适应收集器； 以及分代的那一半，带一张卡表和一道写屏障。收集器对一个程序负责多少，是产物 随身带着的一个数字，两个独立的校验器不看一行源码就能核对它。见 LomentGC。
  2. no_runtime 是保证，不是声明。这个默认值过去的意思是 "这个程序没有请求运行时"。它现在的意思是产物没有运行时：任何会把运行时拖进来 的构造都在编译期被拒。choose runtime 是另一半 —— 它不管程序是否用到 运行时，都把运行时放进去。这是这里唯一一处可能影响你已有程序的改动： 任何用到除法、分配或字符串拼接的东西，都需要在它的根单元里加一行。
  3. 第五个维度：vm。程序现在可以说它是为哪种执行模型而写的。 在发布构建里，那一行是一个编译错误；只有开发通道接受它，而那个通道 产出的东西与 no_vm 逐字节相同。维度与闸门是真的，引擎不是 —— 那一页说明了哪一半是哪一半。
  4. 网络，在两个目标上。同一份源码在 Linux 和 Windows 上从同样的字节 打开套接字。随它一起到来的两处边界，正是仍然缺掉的部分：没有网络库 —— 系统调用要你自己写 —— 以及没有准入闸门，所以一个声明自己不会请求 网络访问的单元，实际上并没有被阻止去调套接字。能力检查比对的是域的名字， 从不看行为。
  5. --opt。装了 clang 之后，构建可以把 IR 交给它并开 -O2，而不是用自带链接器。这是快的那条路，代价是自带那条路存在的理由： 不需要外部工具链。

修复

最后一组来自对表层语法的那轮扫面 —— 也就是一个单元还能被写出来的另外六种方式。每一条 都是前端可能把你写下的东西弄丢的单独一种方式，所以逐条列出，各附其 issue。

  1. Windows 安装器。随 0.1.4 发布的那一个，在被配置成不搜索当前目录找 可执行文件的机器上什么都不做。那一个保持原样；这一版带的是修好了的安装器。
  2. 一条从不复用任何东西的空闲链表。自带链接器对每个 phi 只指派一条 入边，于是分配器的空闲链表终生是空的。
  3. 汇编器拒绝的产物。两个 IR 缺陷让数组下标的产物成了非法的 LLVM。 而收集器自己输出里缺掉的一个块终结符，是项目当时所有判据都看不见的。
  4. 语言服务器与格式化器。服务器不再对一份解析不了的文件崩溃，自举的 格式化器也不再拒绝另外六门表层语法。
  5. 入口点处的栈对齐。进程入口并没有拿到调用约定所假定的那个对齐，所以 _start 把它重新对齐。
  6. C 表层语法里的若干修复，针对前端把某个东西吞掉、或把它报成了别的东西 的那些地方。每一条都有自己的 issue；标签信息把它们列了出来。
  7. 用另一种语法写成的单元可能静默丢掉整个函数：前端把转写侧关于它跳过了什么的报告扔掉了。 #74
  8. loment fmt --write 会毁掉用另一种语法写的文件 —— 它把声明行并进下一行、删掉原本在那里的函数，然后以退出码 0 结束。 #115
  9. loment doc 会在这种文件上崩溃，或者生成出以生成行号、而不是你写下的那些行号为键的文档。 #116
  10. 函数内的 static 被丢弃，于是那个值在两次调用之间留不下来。 #118
  11. 一个局部变量与 for 体外的某个东西同名，会让转写出来的单元无限循环。 #119
  12. 定义在同一行上的第二个函数被静默丢弃。 #122
  13. 一个未加括号的布尔转换生成了一个不再能解析的单元。 #124
  14. 顶层的 typedef、全局变量、union、#include 与 #define 既没被转写也没被报告 —— 检查仍然打印 OK。 #126
  15. 一个八进制字面量让两个命令行工具都打印出了栈回溯。 #127
  16. 外部符号表塌缩成了它的最后一条，于是跨单元那条路根本无法工作。 #128
  17. 一个 K&R 风格的函数定义静默消失 —— 没有条目，没有 [skip] 行，退出码 0。 #129
  18. 一个名为 true 或 false 的变量在它声明的地方被改名了，在它被使用的地方却没有。 #130
  19. 两个标识符在改名之后可能塌缩成一个，丢掉一次赋值。 #134
  20. 一个名字与关键字冲突的函数生成了一个无法做词法分析的单元。 #135
  21. 开头的一个字节序标记让语法声明变得不可见。 #136
  22. 前端接受了词法分析器拒绝的标识符，并把错误报在了一个生成文件上。 #137
  23. 一个没有显式指定语言的 .c 文件被当成 JSON 读了。 #140
  24. 在这种文件里发一次跳转到定义请求会让语言服务器终止。 #142
  25. 诊断工具与前端对哪些语法是原生的意见不一致，于是其中一个撤回了它本应提供的修复。 #145
  26. loment dbg 报告了一个并不存在的文件和行号。 #146
  27. 一个被当作语句使用的调用绕过了跨单元闸门并被丢弃；同一个调用放在值的位置上却被拒绝了。 #147
  28. 一个拼错的语法关键字静默回退到了 Loment，而不是报错。 #148
  29. 一元 ~ 在文档里被说成受支持，却被转写器拒绝。 #150
  30. 表达式语句在文档里被说成受支持、却解析不了 —— 而且报错信息归咎于操作数。 #151
  31. 一个映射不了的返回类型让函数消失了，而错误归咎于它下方好几行处的一个调用点。 #152
  32. 一个函数原型会依它所在的位置，给出三种各不相同、而且都是错的诊断。 #153
  33. 一条越界（不在子集内）诊断在它承诺给出函数名的地方，给的是一个行号和一个函数计数。 #154
  34. 示例附注仍然把 C 那条支线说成链接，而它已经变成了转写。 #155
  35. 一处跨单元名称冲突被用错误的名称报告出来，而且指到了错误的 use 行。 #221

本版没有

libc 与 LibL 都不可用。libc 这条线在把 C 库所需的部件一件一件地造 出来，而标准库那个 C 形状的面还没准备好被使用。今天这两样都不是可以拿来规划的东西 —— LibL 那一页自己带着一条状态说明。

当前状态在哪里
