一门系统编程语言

Loment

Loment 构建的原生可执行文件自己站得住 —— 没有 runtime、没有 libc、 底下什么都没有。程序够得着什么，写在源码里、记在产物里，所以一次构建不必读你的代码， 就能把它检查出来。工具链本身就是用 Loment 写的。

下载 入门 

module hello fn _start() {    let s: str = "hello from Loment\n";    syscall4(1, 1, str_ptr(s) as u64, str_len(s) as u64);    syscall4(60, 0, 0, 0);}

$ loment run hello.lomt
hello from Loment

这就是整个程序。_start 是机器开始的地方，文字经 write 系统调用送出去 —— 一个什么都不链接的程序，底下没有 printf 可以调用。 没有人替你做任何事，也没有什么挡在路上。

两类程序

多数语言在构建文件里决定什么进产物 —— 那个文件，读源码的人从不会打开。Loment 把这个 决定放进程序里：一行，写在你开始的那个文件里，被带进产物随身携带的一份机器可读 摘要。于是"这是一个哪一类程序？"这个问题，不读任何代码就能回答。

choose sealed

它是什么
默认值。一个与外界之间没有任何开口的程序。
入口点
fn _start()
链接
什么都不链。在那里，未定义符号是错误，不是警告 —— 所以可以证明一个 sealed 程序既没有 runtime、也没有 libc。
可达
只有编译进它的代码，加上你交给链接器的、本身已自足的任何目标文件。

choose hosted

它是什么
另一条路径。一个被允许向自身之外伸手的程序。
入口点
fn main() -> u32
链接
真正的库。构建把自己的产物交给宿主的 C 工具链，而不是用 Loment 自带的链接器。
可达
libc、共享库，以及你嵌入的宿主 runtime。项目自己的测试链接 libstdc++ 和 libz，并嵌入 CPython。

边界究竟在哪里。触达一个真正的库，意味着你自己要走宿主工具链 —— 你在构建里点名那个库。一个真正的 C 库还不是可安装的依赖：包管理器目前只接受 Loment 源码库。那部分仍在建。

一个程序被允许碰什么

多数语言回答的问题是这个程序能做什么？ —— 而答案通常是"想做什么就做什么"。 Loment 围绕一个更窄的问题来构建：这个程序被允许够到什么，而这件事能不能在不读它 源码的情况下断定？有三样东西承担它，而第一样在代码里就看得见。 

module native_cap capability blk_write : disk[0..4] revocable fn write(slot: u32) -> u32 {    guard blk_write(slot);    return slot;} fn literal_ok() -> u32 {    guard blk_write(2);    return 2;}

第 3 行声明了一个单元可达的范围。第 6 行在运行期拿 slot 去核它，越界的 下标会让程序停下。第 11 行是字面量，所以编译器提前就把它裁定了，不生成任何东西。

代码自己声明的范围

一个单元 —— 一个源文件加它导入的东西 —— 声明它可达的范围，由 guard 把每一次访问拿去核它：下标是常量时在编译期核，否则在运行期核。 Loment 把这叫一个能力域，并且把边界明说出来、而不是含糊带过 —— guard 约束的是下标，不是主体，它也不是授权。

产物随身携带的一份摘要

每个单元都导出一份机器可读的摘要，说明它包含什么、够到什么，并由两个独立的程序来核。 于是"这个能碰到什么？"有了一个不用读你代码就能得到的答案。这份摘要有个名字： 形式对象。

从另外十门语言调用代码

C、C++、Rust 和 Zig 走 C ABI 进来；Go、Python、Java、JavaScript、Perl 和 Lua 走一个进程桥。在一个 sealed 程序上，你链进来的东西必须自足。 choose hosted 是通向真正的库的那条路，项目自己的测试拿它去跑 libstdc++、libz 和一个嵌入的 CPython。

它已经被用来做什么

一门这么年轻的语言，通常是被拿它希望成为什么来描述的。下面是 Loment 已经在做的事 —— 全都在仓库里，全都可以下载。

工具链

编译器、链接器、格式化器、语言服务器和包管理器都以 Loment 源码的形式发布，运行时 底下没有 Python。编译器是用这门语言写成的最大一个程序。

一个磁盘驱动

ahci.lomt 跟一块 SATA 盘对话：它读寄存器块、数出实现了的端口、 发出命令。寄存器块由调用方递进来，所以同一份代码既能跑在操作系统里，也能跑在 hosted 机器上。

一个终端界面

lumtui 往终端里画文字、方框和布局 —— 一个小库，写法就跟你自己会写 的那样。

编译器在 loment/selfhost/ 下， 库在 loment/lib/ 下， 示例在 loment/examples/ 下。

还有什么不一样

整个程序的设置，就在一行里

一行，写在你开始的那个文件里，就定下整个程序的五件事：它可以用库的哪一层、它如何 回收内存、它能否携带一个 runtime、它能否向自身之外伸手、以及它是为哪种执行模型而 写的。要两个互相矛盾的设置，编译器会拒绝 —— 把两个都点出来、并说出为什么，而不是 一句"非法组合"。这个机制叫 choose。

用另外六种表层语法书写

C、C++、Java、C#、Go 或 Python。变的只是拼写；含义永远是 Loment 的 —— 它是一种 语法，不是一套语义，每个前端都在自己的第一行这么说。

一个一次只导入一个模块的库

标准库随工具链一起发布，你一次触达一个模块：use vec、use map、 use fs。存在一种整包导入，它会把所有东西一次拉进来，文档不建议这么做。

一切皆可定制

源码后缀、你能运行的命令集、库 —— 一个以内容哈希为身份的目录 —— 以及工具链本身。 没有注册表；扩展点是磁盘上的文件。

还没有完成的部分。工具链在没有 Python、没有 libc 的情况下编译并运行 —— 但开发侧还不是这样：参考实现及其测试套件仍在仓库里，仓库也还不是"只有 Loment"。发布 说明会写清每个待办项落在哪一半。

系统

Loment 里大到值得有各自设计记录的四部分 —— 每一部分都带着自己诚实的现状说明， 包括那个引擎还不存在的。

LomentGC 内存由四种策略之一来释放，在每个发生的地方各自挑一种 —— 而留给收集器多少，写进了产物里。 LVM — Loment VM 另一种跑法 —— 产物交给执行器按需收编。引擎并不存在，那一页把它写在最前面。 lompi 一个库就是一个装满 Loment 文件的目录。没有清单语言，没有版本求解器，身份是一个内容哈希。 LibL 标准库，做成 C 的形状：用 C 的名字、C 的参数序，比的是真 glibc，而不是 Python。
