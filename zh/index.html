一门系统编程语言

Loment

它编译为原生 x86-64 可执行文件 —— Linux ELF、Windows PE，或一个面向裸机的 freestanding 目标。什么被放进产物里，是程序的决定，而构建会把它记录下来。 工具链本身就是用 Loment 写的。

下载 入门 

module hello fn _start() {    let s: str = "hello from Loment\n";    syscall4(1, 1, str_ptr(s) as u64, str_len(s) as u64);    syscall4(60, 0, 0, 0);}

$ loment run hello.lomt
hello from Loment

_start 是入口点，因为 sealed（封闭）产物没有 runtime 来替你调用入口。 这里也没有 printf —— 输出走 write 系统调用。

一份源码，两类产物

多数构建设置活在语言之外，读源码的人从来看不到它们。Loment 把这一项放进程序里 —— 一行，写在根单元 —— 然后把它带进单元导出的形式对象里。于是"构建的是哪一类产物"这件事， 由一个完全读不了源码的东西就能回答。

choose sealed

它是什么
默认值。一个与世界之间没有任何端口的产物。
入口点
fn _start()
链接
什么都不链。未定义符号是错误，不是警告 —— 所以 sealed 产物可证明地没有 runtime、也没有 libc。
可达
只有编译进它的代码，加上你交给链接器的、本身已自足的任何目标文件。

choose hosted

它是什么
另一条路径。一个被声明为允许向自身之外伸手的产物。
入口点
fn main() -> u32
链接
真正的库。构建把 IR 交给宿主的 C 工具链，而不是自带的链接器。
可达
libc、共享库，以及你嵌入的宿主 runtime。项目自己的判据链接 libstdc++ 和 libz，并嵌入 CPython。

边界究竟在哪里。触达一个真正的库，意味着你自己要走宿主工具链 —— 你在构建里点名那个库。一个真正的 C 库还不是可安装的依赖：包管理器目前只接受 Loment 源码库。那部分仍在建。

谁能运行什么，在什么范围内

多数语言回答的是这个程序能做什么？Loment 围绕一个更窄的问题组织 —— 谁能运行什么、在什么范围内、以及这件事能否在不读源码的情况下裁定？ 有三样东西支撑它。 

module native_cap capability blk_write : disk[0..4] revocable fn write(slot: u32) -> u32 {    guard blk_write(slot);    return slot;} fn literal_ok() -> u32 {    guard blk_write(2);    return 2;}

第 3 行声明了一个单元可达的范围。第 6 行在运行期拿 slot 去核它，越界的 下标会陷入。第 11 行是字面量，所以编译器就把它裁定了，不生成任何东西。

能力域

一个单元声明自己可达的范围，由 guard 拿一个下标去核它 —— 下标是字面量时 在编译期核，否则在运行期核。边界被明说出来，而不是含糊带过：guard 约束的是下标， 不是主体，它也不是授权。

形式对象

每个单元都导出一份被声明、机器可读的摘要，说明它包含什么、触达什么，并由两个独立的 校验器判定 —— 于是"这个能碰到什么"无需读源码就能回答。

一层兼容层

C、C++、Rust、Zig 在 C ABI 之后；Go、Python、Java、JavaScript、Perl、Lua 走一个 进程桥。在 sealed 产物上，链进来的东西必须自足。choose hosted 是触达 真正的库的那条路径，判据拿它去练 libstdc++、libz 和一个嵌入的 CPython。

还有什么不一样

一种项目模式，不是 crate 属性

choose 有四个维度 —— 程序可用哪一层、如何回收内存、产物能否携带一个 runtime、以及能否向自身之外伸手。每一个都最多写一次，写在根单元里，且各自成为整个 程序的一个属性：一对矛盾的组合会被拒绝，诊断会点名那一对和理由，而不是只说 "非法组合"。

用另外六种表层语法书写

C、C++、Java、C#、Go 或 Python。变的只是拼写；含义永远是 Loment 的 —— 它是一种 语法，不是一套语义，每个前端都在自己的第一行这么说。

一个一次只导入一个模块的库

标准库随工具链一起发布，以 use vec、use map、 use fs 的方式触达。存在一种整包导入，但它会把所有东西拉进一个单元， 文档不建议这么做。

一切皆可定制

源码后缀、命令面、库 —— 一个以内容哈希为身份的目录 —— 以及工具链本身。没有注册表； 扩展点是磁盘上的文件。

还没有完成的部分。工具链在运行期是自举的 —— 它在没有 Python、没有 libc 的情况下编译并运行 —— 但开发侧不是：参考实现及其测试套件仍在仓库里，仓库也还不是 "只有 Loment"。发布说明会写清每个待办项落在哪一半。

三个系统

Loment 的三个部分，大到值得有各自的设计记录 —— 以及各自诚实的现状说明。

LomentGC 回收作为一份逐站点的契约：一座四层阶梯，以及收集器该负责多少被写进产物。 LVM — Loment VM 第五个维度与一道闸门，在建。引擎并不存在，那一页把它写在最前面。 lompi 一个库就是一个装满 Loment 文件的目录。没有清单语言，没有版本求解器，身份是一个内容哈希。
